# Review System Overview

The authoritative runtime package is `skills/teim-review/`. Every distribution
uses its unchanged `SKILL.md`, references, schemas, and scripts. Plugin and
marketplace files provide discovery metadata; there are no separate workflow
adapters or hand-maintained package mirrors.

## Workflow ownership

- `SKILL.md`: discovery, resource roots, scope, and delegation fallback.
- `references/workflow.md`: deterministic preparation and review sequencing.
- `references/finding-policy.md`: finding criteria and admission rules.
- `references/reviewer.md`: candidate generation.
- `references/validator.md`: validation of existing candidates.
- `references/quick-rules.md`, `references/comprehensive-guide.md`, and
  `references/knowledge/`: curated review knowledge.
- `references/schemas/`: unchanged candidate, validated, and final report formats.
- `scripts/`: deterministic preparation, assembly, normalization, and HTML.

`skill_root` locates installed resources. `project_dir` locates the code and
project instructions being reviewed. `output_dir` locates generated artifacts.
The workflow must not assume the skill's source checkout is the target project.

## Execution

Use general-purpose subagents with the bundled reviewer and validator prompts
when the harness supports and permits them. Run those roles sequentially in the
main thread otherwise. Candidate findings must exist before validation starts.
Keep schemas and policy identical for both execution modes and disclose which
mode was used. A main-thread second pass is not independent validation.
Delegation is required when available and permitted, rather than an optional
optimization. A fallback must name the missing capability or binding permission;
a failed subagent does not justify silently switching execution modes.

The skill does not select models or configure model tiers. The interactive
harness controls its model, and CI selects a single model through job variables.

## CI

`ai_code_review` prepares context deterministically and invokes Claude once.
The prompt reads the portable skill with `execution_mode: zuul` and
`findings_only: true`. It writes candidate and validated findings and returns
the validated object through Claude's existing structured-output contract.
The caller then assembles the report, normalizes routing, renders HTML, and
publishes comments and artifacts. Named Claude agents are not required.
Claude CI runs without `--bare`, auto-approves built-in `Agent`/`Task` delegation, and
requires separate reviewer and validator subagents.
Startup ignores ambient user/project settings, disables hooks, and restricts
MCP configuration to an empty server set. This retains isolation from reviewed
project executable configuration while exposing delegation.
The trusted settings file generated by `ai_review_setup` is loaded explicitly
with `--settings`, preserving CI's model alias mappings. That file disables
hooks; excluding ambient settings must not exclude these generated mappings.
The role checks Claude's execution
metadata for at least two spawned and completed subagents with no failures
before report assembly. Missing metadata or main-thread-only execution fails
the job. These counts detect omitted delegation; role assignment and sequencing
remain requirements of the shared workflow and CI prompt.

Diagnostics are saved under `code-review/claude/`: each invocation attempt gets
a recorded session UUID and `debug-<UUID>.log`, enabled with `--debug-file`.
Post-run collects that attempt's main transcript and subagent JSONL/metadata
under `sessions/`, even when no final result was produced. `collection.json`
lists collected files and sessions with no transcripts. Retries retain separate
logs and session IDs. Collection excludes other sessions and Claude settings or
credential files. These artifacts contain review prompts, source, and tool
output and are published with the other review artifacts.

## Distribution

Claude, Codex, and Cursor manifests point at the same root `skills/` tree.
`package.json` exposes that tree as a Pi package. The Vercel Skills installer
can install the individual skill into Claude, Codex, Cursor, OpenCode, and Pi.
Do not install the same skill through multiple mechanisms in one harness.

The skill folder is self-contained. Scripts, schemas, examples, policy, and
curated knowledge must remain usable when copied without the rest of the repo.
The three sibling skills provide security audits, maintainability audits, and
document conversion independently of this review workflow. The audit skills
require explicit user invocation; document conversion permits tool/model
discovery. The plugin exposes all siblings from the shared `skills/` tree.
Preparation agents and native agent-directory aliases have been removed.

## Agent Plugins specification

The reviewed specification checkout is `agentplugins/agent-plugins-spec` at
its published 1.0.0 contract; 1.1.0 is a working draft. Root `plugin.json`
targets the canonical 1.0.0 schema. Skills are discovered under `skills/`
without a `skills` field in that portable manifest. Paths supplied by the
package must stay inside its root after filesystem resolution.

The standard deliberately covers skills and MCP rather than native agents,
hooks, or rules. That fits this repository: reviewer and validator are bundled
role instructions, with optional harness delegation and a main-thread fallback.
No MCP server or runtime extension is needed for this review workflow.

Native manifests remain compatibility metadata. Their presence does not imply
that every client supports Agent Plugins 1.0.0; direct skill installation is
also supported. The skill remains independently installable without root files.

- [Published Agent Plugins 1.0.0 specification](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md)
- [Working draft 1.1.0](https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.1.0.md)

## Skillsaw linting

Skillsaw's reviewed revision is pinned in `.pre-commit-config.yaml`. The
existing `tox -e linters` and Zuul lint job therefore check portable and native
manifests, routing frontmatter, bundled references, and common directory layout.
Schemas live under `references/schemas/` to keep the skill root conventional.
The entrypoint stays short and loads workflow, policy, role prompts, and coding
references progressively. Scripts are included only when the workflow uses them.

`.skillsaw.yaml` pins the rules version and enables `agentskill-structure`.
Structural errors fail the gate; advisory content findings remain visible.
There is no baseline or blanket suppression. Every sibling skill is checked
for structure, routing metadata, bundled resources, and content guidance.
